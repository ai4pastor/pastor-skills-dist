# 보강 모드 — 완성 설교문 보강 제안 규칙

이미 완성된 설교문을 읽고, **설교를 고치지 않으면서** 더 참고하면 좋을
연구자료·다른 관점·놓친 배경을 제안한다. 등급 규칙은 `references/grade_rules.md`,
웹 검증은 `prompts/verify_facts.md`(예산: config `search_budget.enrich`, 기본 5회)를 따른다.

## 대원칙: 재작성 금지

- 설교문의 문장·구조·논지를 고치거나 첨삭하지 않는다. 대안 문장을 제시하지 않는다.
- 설교 원문을 보강노트에 복사하지 않는다 — wikilink로만 연결한다.
- 모든 제안은 "참고하시면 좋을" 제안의 언어로 쓴다. 채택은 목사님의 몫이다.

## 절차

1. **설교 읽기**: 본문(주 성경구절), 중심 논지, 이미 사용된 자료·예화를 파악한다.
2. **기존 연구노트 연결 (있을 때만)**: 지난번 연구노트 저장 폴더가 기억되어 있으면
   (`config_loader.py`의 memory) `ls`로 확인해 같은 본문의 연구노트를 찾는다.
   실제로 존재하는 파일만 `links.관련연구`로 연결하고, 거기 없는 내용만 새로 제안한다.
   **링크를 지어내지 않는다.**
3. **설교 속 사실 점검(조용히)**: 설교에 이미 들어 있는 사실 주장 중 오류가 의심되는 것만
   검증한다. 문제가 있으면 "확인해 보시면 좋을 부분"으로 정중히, 근거와 함께 알린다.
   문제없는 것을 일일이 칭찬하거나 나열하지 않는다.
4. **보강 주장 원장**: 새로 제안하는 사실 자료를 `work/claims.json`에 정리하고
   웹 검증 → `verify_claims.py` 게이트 통과.
5. **result JSON** → `~/.pastor-sermon-lab/work/enrich.json`. 이후 SKILL.md 흐름 Step 3~6.

## result JSON 스키마 (enrich)

```json
{
  "title": "설교 제목",
  "topic": "파일명용 짧은 제목",
  "date": "YYYY-MM-DD (오늘)",
  "main_passage": "히 11:1-6",
  "verification_status": "웹검증 완료 | 오프라인",
  "search_count": 0,
  "links": {"설교노트": "260713_믿음의 길", "관련연구": "2026-07-10_연구_히11"},
  "tags": ["한단어태그"],
  "body": "## 추가로 살펴볼 자료\n..."
}
```

## body 섹션 구성

1. `## 추가로 살펴볼 자료` — 원어·배경·역사 자료 2~4개. 사실 주장마다 등급 필수.
   설교에 이미 있는 내용과 겹치지 않게.
2. `## 다른 관점 (해석)` — 본문을 읽는 다른 각도·반대 견해 1~3개. 설교 논지를
   반박하기 위해서가 아니라 시야를 넓히기 위한 것임을 분명히 한다.
3. `## 예화 각도 (해석)` — 예화 소재의 방향 제안 (완성된 예화 원고가 아니라 각도만).
4. `## 연결 가능한 다른 본문` — 같은 주제의 성경 본문 2~4개, 연결 이유 한 줄씩.
5. `## 확인해 보시면 좋을 부분` — 3번에서 발견된 사항이 있을 때만. 근거·출처 필수.

## 금지

- 설교문 첨삭·대안 문장·구조 개편 제안 (그건 진단 모드의 영역도 아니다).
- 설교문 문장을 웹 검색 질의에 넣기 (사실 키워드만).
- 등급 없는 사실 자료 제안, 존재를 확인하지 않은 서지·인용 제안.
