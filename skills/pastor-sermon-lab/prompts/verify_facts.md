# 웹 교차검증 프로토콜

핵심 사실을 WebSearch로 교차검증해 등급을 확정한다. 등급 규칙은
`references/grade_rules.md`가 단일 권위다. 이 문서는 "무엇을, 몇 번, 어떻게" 검색하는지 정한다.

## 검증 트리거 (주장 유형)

| 유형 | 대상 | 검증 |
|---|---|---|
| T1 | 고고학 유물 + 카탈로그 번호/소장처 | 항상 |
| T2 | 학자 실명 + 저작·논문 인용 | 항상 |
| T3 | 통계·수치 (인구, 거리, 백분율) | 핵심 논지(load_bearing)일 때 |
| T4 | 신학자·역사 인물의 직접 인용문 (인용부호 사용 시 무조건) | 항상 |
| T5 | 역사 사건 연대·통치자 재위 | 핵심 논지일 때 |
| 비트리거 | 성경 본문 내용, 상식 수준 배경, 신학적 해석 | 검색 없이 🟡 이하 또는 (해석) |

## 검색 예산

- 모드별 상한 고정: 연구 12 / 보강 5 / 진단 3 (`config_loader.SEARCH_BUDGET`).
- `verify_claims.py --plan`이 예산 안에서 검증 대상을 우선순위(load_bearing 우선)로 뽑아준다.
- 관련 주장은 질의 1개로 묶는다 — 예: "Tel Dan stele date museum" 하나로 연대·소장처·판독 논쟁을 동시 수집.
- 예산 초과분은 🟡 상한 + 원장에 미검증으로 남긴다. 목사님이 원하면 추가 검증 라운드를 제안한다.

## 판정 기록

- 검색 결과마다 evidence 항목을 원장에 기록: `{"url": "...", "domain": "...", "agrees": true|false}`.
- `agrees`는 주장과 출처 내용의 일치 여부다. 반박이면 false로 기록한다 — 버리지 않는다.
- 등급 확정은 `grade_rules.md`의 승격·강등 표를 그대로 적용한다. 재량 없음.

## 오프라인 폴백 (WebSearch 불가 시)

1. 원장 `web_available: false` 기록.
2. 웹검증 대상 주장은 전부 🟡 상한 (✅는 script source만 가능).
3. result JSON `verification_status: "오프라인"`.
4. 노트 본문 맨 앞에 배너: `> ⚠️ 이 노트는 웹 교차 검증 없이 작성되었습니다 (오프라인)`.

## 프라이버시 (절대 규칙)

검색 질의에는 사실 주장의 키워드만 넣는다. 설교문 문장, 교인·회중 정보,
목사님 개인 정보(이름·교회명 포함)는 질의에 넣지 않는다.
