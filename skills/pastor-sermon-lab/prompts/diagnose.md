# 진단 모드 — 설교 초안 진단 규칙

설교 초안을 회중의 귀로 듣고, 고정 6차원 루브릭으로 진단한다.
루브릭은 `references/rubric.md`가 권위다.

## 절차

1. **회중 확인 (질문 1개)**: `config_loader.py`의 memory에 `congregation`이 있으면
   "지난번처럼 {요약} 기준으로 들어볼까요?"라고 확인만 한다. 없으면 딱 하나만 묻는다:
   "회중이 주로 어떤 분들이세요? (연령대, 직장인/청년/어르신 비율 같은 것을 편하게요)"
   답을 받으면 `python3 scripts/config_loader.py --remember-congregation "{한 줄 요약}"`으로 기억한다.
2. **회중 관점 만들기**: 회중 서술에서 서로 다른 청취자 2~3명을 즉석에서 그린다
   (예: "40대 직장인", "침체기 청년"). 발화 무결성 규칙:
   - 발언 내용은 (회중 서술 + 설교 본문) **두 출처에서만** 나온다. 구체 인명·사건을 지어내지 않는다.
   - 회중이 모를 신학 용어에는 아는 척 대신 "무슨 뜻인지 몰랐어요"로 반응한다 — 그것이 진단 신호다.
   - 외부 통계·학자 인용 금지. 설교에 없는 성경·교리를 청취자 입으로 만들지 않는다.
   - 반응마다 설교문의 실제 구절을 1개 이상 짚는다 ("○○ 부분에서…").
   - 듣기 좋은 말만 하지 않는다.
3. **지난 진단과 비교**: 저장 폴더(지난번 진단 폴더가 기억되어 있으면 그곳)를 `ls`로 확인해
   `_진단_` 노트가 있으면 최근 1~3개의 frontmatter(`점수_*`, `약점`)를 읽어 비교한다.
   같은 차원이 반복해서 약점이면 세션 서두에 알린다:
   "지난 진단에서도 {차원}이 약점이었습니다. 이번에 집중해서 보겠습니다."
   지난 노트가 없으면 첫 진단임을 알린다. **노트를 지어내서 참조하지 않는다.**
4. **6차원 채점**: 루브릭 앵커를 인용하고 설교 본문 근거를 붙여 채점한다.
   약점 = 점수 2 이하 차원 (전부 3 이상이면 최저점 1개). 반복 약점이 있으면 `focus`로 지정.
5. **result JSON** → `~/.pastor-sermon-lab/work/diagnose.json`. 이후 SKILL.md 흐름 Step 3~6.

## result JSON 스키마 (diagnose)

```json
{
  "title": "설교 제목",
  "date": "YYYY-MM-DD (오늘)",
  "scores": {"본문충실": 4, "중심명제": 3, "구조명료": 4, "적용구체": 2, "예화적절": 3, "회중공감": 3},
  "weaknesses": ["적용구체"],
  "focus": "적용구체",
  "tags": ["설교진단"],
  "body": "## 한 줄 진단\n..."
}
```

## body 섹션 구성

1. `## 한 줄 진단` — 강점 1 + 최우선 개선점 1을 담은 한 문장.
2. `## 차원별 진단` — 6차원 각각: 점수, 루브릭 앵커 인용, 설교 본문 근거 인용.
3. `## 회중 반응` — 청취자별 1인칭 반응 2~3개.
4. `## 이번 설교의 강점` — 2~3개, 본문 근거와 함께.
5. `## 지난 진단과의 대조` — 3번 결과 기반. 첫 진단이면 "첫 기록"이라고 쓴다.
6. `## 다음 설교를 위한 한 가지` — 딱 하나만. 지시가 아니라 제안의 언어.

## 금지

- 설교문 다시 쓰기·문장 첨삭.
- 점수 근거 없는 채점, 회중 반응과 모순되는 회중공감 점수.
- 설교문 내용을 웹 검색 질의에 넣는 것. 사실 오류가 의심될 때만 키워드로 최대 3회.
