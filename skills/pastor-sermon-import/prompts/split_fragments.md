# Sermon Split Prompt

설교 본문을 Obsidian 조각 노트로 나눌 수 있는 의미 단위로 분해한다.

이 결과 하나가 **메인 노트의 `## [[제목]]` 섹션과 조각 파일 둘 다**를 만든다.
따라서 제목은 파일명이 되고, 글머리는 두 곳에 같은 내용으로 들어간다.

`use_word: true`면 설교 전체의 WORD 분류(`prompts/word_classify.md`)도 **이 분석에서
함께** 만든다 — 본문을 두 번 읽지 않는다. 조각을 모두 나눈 직후가 설교 전체의
주제를 가장 정확히 아는 순간이다.

**나만의 규칙 파일**: `paths.py` 출력의 `custom_rules` 파일이 있으면
(`custom_rules_exists: true`) 먼저 읽는다. 그 파일의 지시가 이 문서의
**문체·글머리 구성·개수 규칙보다 우선**한다 — 목사님이 자기 취향대로 조각을
다듬는 통로이며, 플러그인을 업데이트해도 유지된다. 단 아래는 바꿀 수 없다:
본문에 없는 내용 추가 금지, 허용 목록 밖 분류값 금지, JSON 출력 스키마, 원본 보존.

## 조각 기준

한 조각 = 독립된 메모로 가치가 있는 한 단위:

- 핵심 논지 1개
- 성경해석 단위 1개
- 예화 1개
- 적용 1개
- 신학 개념 설명 1개

**개수는 설교의 길이와 내용에 비례한다** — 개수를 목표로 잡지 않는다:

- 설교의 실제 논리 단위 수를 따른다. 보통 설교는 3~8개에 들어가지만 **상한이 아니다 —
  긴 설교는 10개 이상도 정상이다.**
- 억지로 채우지도 않고, 반대로 **한 조각에 다 안 들어가는 내용을 욱여넣어 개수를 맞추지도
  않는다.** 넘치면 조각을 나눈다.
- 판별 테스트: "이 조각이 정말 별도 메모로 가치가 있는가?" 두 조각이 50% 이상 겹치면 합친다.
- **한 논지를 설명하기 위한 짧은 비유·사례는 별도 조각으로 만들지 말고 그 논지 조각의 글머리로 흡수**한다. 독립적으로 재사용할 가치가 있는 예화만 별도 조각으로 분리한다.

## 제목 기준

| 항목 | 본 메시지 (argument·exposition·application·doctrine) | 예화 (illustration) |
|---|---|---|
| 길이 | 한국어 **10~20자** | 한국어 **15~25자** |
| 형식 | **명제형** — `X는 Y다` / `X 없이는 Y하지 못한다` / `X가 아니라 Y다` | `💡 {비유명} - {핵심 메시지}` |
| 금지 | 한 단어(`은혜`), 라벨형(`계시의 필요성`, `~에 대하여`, `~의 차이`, `~한 태도`) | `💡` 누락, ` - ` 구분자 누락 |

파일명이 되므로 `:` `?` `/` `\` `*` `<` `>` `|` `"` `#` `^` `[` `]` 를 쓰지 않는다.

**약한 제목 → 강한 제목**

| 약함 (라벨) | 강함 (명제) |
|---|---|
| 인간의 유한성과 계시의 필요성 | 유한한 인간에게 계시는 필수다 |
| 일반계시와 특별계시의 차이 | 일반계시로는 구원에 이르지 못한다 |
| 계시에 대한 올바른 태도 | 말씀 앞에서는 경청이 먼저다 |
| 은혜 | 은혜는 값을 치른 사람이 따로 있다는 뜻이다 |

판별 테스트: 6개월 뒤 검색 결과에서 **제목만 보고 무슨 주장인지 안다면** 좋은 제목이다.

## 글머리(bullets) 기준

- **개조식으로 쓴다** — 조각은 산문이 아니라 메모다. 완결 서술문(`~이다`, `~한다`)이 아니라
  명사형·압축 종결(`~임`, `~없음`, `~하심`, `~해야 함`)로 끝낸다
- **한 글머리 = 한 아이디어.** 주장과 그 이유·부연은 한 줄에 압축한다: `주장 — **이유·결론**`.
  서로 다른 논지는 글머리를 나눈다
- 조각당 3~5개 (내용이 많으면 6개까지), 한국어 15~60자 — **줄 수를 늘리지 말고 밀도를 높인다**
- 기호 용법: `=`는 정의·요점 압축 전용 (`행복의 조건 = **감사하는 삶**`),
  `—`는 주장 뒤 이유·부연 전용, `→`는 실천 적용·성찰 질문·귀결 전용
- 본문 맥락만 사용 — 임의 추론·일반론 금지
- 본문 표현·인용·성경구절 표기를 그대로 살린다 — 설교 속 직접화법은 따옴표로 보존
- **조각당 1~3곳 볼드** — 글머리 끝의 결론·이유 자리(`—`나 `=` 뒤)나 핵심 구절에 둔다.
  볼드만 이어 읽어도 설교 논리가 재구성되게. 전부 볼드 금지 (변별력 상실)
- 성경 인용은 독립 글머리로: `구절 표기 — "번역 본문 그대로"` (긴 인용은 `…` 압축 허용)
- 설교 결론부의 성찰 질문들은 마지막 조각에 `→` 글머리로 나열

### 예화 조각(`kind: illustration`)의 글머리 3단 구성

1. 예시의 출처·내용 (1~2줄)
2. 핵심 메시지·교훈 (1줄)
3. 이 설교에서 어떻게 적용되었는지 (1줄)

## 기존 조각 재활용 (필수 확인)

제목을 지었으면 확정하기 전에 볼트의 기존 조각과 대조한다:

1. 이 설교(청크)의 조각 제목 초안들을 JSON으로 저장한다: `{"titles": ["초안1", "초안2", ...]}`
2. 근접 후보를 받는다:

   ```bash
   python3 scripts/list_fragments.py --config "{config}" --match-file "{초안 JSON}" --extra "{fragments_dir}"
   ```

3. 초안마다 돌아온 후보 몇 개만 보고 판단한다 — **의미가 같은 후보가 있으면
   새로 짓지 말고 그 제목을 글자 그대로 쓴다.** 없으면 초안을 그대로 쓴다.

`--extra`는 이번 배치의 앞 청크가 이미 지은 제목까지 대조에 포함시킨다.
가운뎃점(`·`)과 공백, 어순, 단어 하나 차이가 모두 다른 파일을 만든다.
비슷하지만 다른 제목을 새로 지으면 같은 생각이 조각 두 벌로 갈라진다.
(볼트 조각이 100개 미만이면 옵션 없이 실행해 전체 목록을 직접 봐도 된다.)

## 조각별 분류

- `doctrine`: config의 `classification.doctrine_values` **허용 목록 안에서만**, 그 조각 내용 기준 1~3개. 적절한 값이 없으면 빈 배열. `use_word: false`면 생략.
  - 설교 전체의 분류를 그대로 복사하지 않는다. 그 조각이 실제로 다루는 주제만 고른다.
  - 탐색 순서: 설교 전체 doctrine 후보를 먼저 검토하되, 조각 내용이 요구하면 목록의 다른 값을 쓴다.
- `tags`: 한 단어 한국어 3~8개, **띄어쓰기 절대 금지** (`전능하신하나님` ✓ / `전능하신 하나님` ✗). 너무 일반적인 단어(노트, 정리, 설교) 금지.

## 출력 형식 (JSON)

`build_notes.py --fragments`에 그대로 입력할 수 있는 형식으로 저장한다.
`title` / `kind` / `bullets` / `doctrine` / `tags` **외의 필드는 넣지 않는다.**

```json
{
  "{입력 파일명}": [
    {
      "title": "유한한 인간에게 계시는 필수다",
      "kind": "argument",
      "bullets": [
        "인간이 먼저 아는 것은 하나님을 찾을 능력이 아니라 **찾을 수 없다는 한계**",
        "[[욥11_7]] — \"네가 하나님의 오묘함을 어찌 능히 측량하며\"",
        "**하나님을 아는 지식은 발견이 아니라 계시로 옴** — 방향이 위에서 아래",
        "물속의 물고기가 물 전체를 볼 수 없는 것과 같음 — 안에 있는 자는 밖을 못 봄",
        "신학의 출발점 = 인간의 탐구가 아니라 **하나님의 말 걸어오심**"
      ],
      "doctrine": ["🔖계시"],
      "tags": ["계시", "유한성", "하나님지식"]
    },
    {
      "title": "일반계시로는 구원에 이르지 못한다",
      "kind": "exposition",
      "bullets": [
        "[[롬1_20]] — \"그의 보이지 아니하는 것들이… 만물에 분명히 보여 알려졌나니\"",
        "자연과 양심이 알려 주는 것은 하나님이 계시다는 사실까지 — **누구신지, 어떻게 나아가는지는 알려 주지 않음**",
        "같은 본문이 20절에서 알림을, 21절에서 그 알림을 거절한 인간을 말함",
        "일반계시의 한계 = 사람을 변명할 수 없게 하지만 **구원하지는 못함**"
      ],
      "doctrine": ["🔖계시", "🔖구원"],
      "tags": ["일반계시", "로마서1장", "변명"]
    },
    {
      "title": "💡 지도 없는 등산객 - 방향 감각만으로는 정상에 못 간다",
      "kind": "illustration",
      "bullets": [
        "나침반만 든 등산객은 북쪽은 알아도 등산로는 모름 — 방향을 아는 것과 길을 아는 것은 다름",
        "**길은 먼저 걸어 본 사람이 알려 줘야 함**",
        "본 설교 적용: 일반계시 = 나침반, 성경 = 지도"
      ],
      "doctrine": ["🔖계시"],
      "tags": ["비유", "일반계시", "특별계시"]
    },
    {
      "title": "성경은 하나님이 스스로 말씀하신 기록이다",
      "kind": "doctrine",
      "bullets": [
        "[[딤후3_16]] — \"모든 성경은 하나님의 감동으로 된 것으로\"",
        "\"감동으로 되었다\" = 사람이 썼지만 **하나님이 말씀하셨다는 뜻**",
        "저자가 둘이 아니라 한 저자가 사람을 통해 말씀하신 것 — 그래서 성경은 인간의 견해 모음이 아님",
        "[[벧후1_21]] — \"오직 성령의 감동하심을 받은 사람들이 하나님께 받아 말한 것이니라\""
      ],
      "doctrine": ["🔖계시", "🔖성령사역"],
      "tags": ["성경론", "영감", "디모데후서"]
    },
    {
      "title": "말씀 앞에서는 경청이 먼저다",
      "kind": "application",
      "bullets": [
        "계시가 위에서 온다면 첫 자세 = 평가가 아니라 **경청**",
        "[[삼상3_10]] — \"말씀하옵소서 주의 종이 듣겠나이다\"",
        "성경을 내 생각의 근거로 쓰는 것과 성경 앞에 내 생각을 두는 것은 **전혀 다른 자세**",
        "→ 나는 말씀을 읽을 때 확인하러 가는가, 들으러 가는가",
        "→ 내 생각과 부딪힌 대목에서 말씀을 조정했는가, 나를 조정했는가"
      ],
      "doctrine": ["🔖순종", "🔖묵상"],
      "tags": ["경청", "말씀묵상", "적용"]
    }
  ]
}
```

위 예시에서 확인할 것:

- 다섯 조각 모두 제목만 읽어도 설교 논리가 순서대로 재구성된다
- **글머리가 전부 개조식이다** — `~옴`, `~못함`, `~아님`으로 끝나고, `=`와 `—`로 주장·이유가
  한 줄에 압축된다. 완결 서술문(`~이다`)으로 풀어 쓴 글머리가 하나도 없다
- 짧은 비유(물속의 물고기)는 **글머리로 흡수**되고, 재사용 가치가 있는 등산객 비유만 `💡` 조각이 됐다
- 성경 인용은 독립 글머리이고 `[[책장_절]]` 형태다 (링크는 스크립트가 검증한다)
- 마지막 조각에 `→` 성찰 질문이 모였다
- 조각별 `doctrine`이 다르다 — 설교 전체 분류의 복사가 아니다

`kind`는 `argument`(논지) / `exposition`(해석) / `illustration`(예화) / `application`(적용) / `doctrine`(교리 설명) 중 하나.

## 금지

- 본문에 없는 내용을 새로 추가하지 않는다.
- 설교자의 문체를 임의로 고치지 않는다.
- 조각 개수를 억지로 늘리지 않는다. 반대로 개수를 줄이려고 서로 다른 논지를 한 조각에 욱여넣지도 않는다.
- 허용 목록에 없는 doctrine 값을 만들지 않는다.
- JSON 스키마 밖의 필드·섹션·설명문을 추가하지 않는다.
- `## 관련 노트`, `See also`, `References` 같은 링크 모음을 만들지 않는다. 노트 본문 구조는 스크립트가 전부 결정한다.
