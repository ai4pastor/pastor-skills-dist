# Sermon Split Prompt

설교 본문을 Obsidian 조각 노트로 나눌 수 있는 의미 단위로 분해한다.

이 결과 하나가 **메인 노트의 `## [[제목]]` 섹션과 조각 파일 둘 다**를 만든다.
따라서 제목은 파일명이 되고, 글머리는 두 곳에 같은 내용으로 들어간다.

## 조각 기준

한 조각 = 독립된 메모로 가치가 있는 한 단위:

- 핵심 논지 1개
- 성경해석 단위 1개
- 예화 1개
- 적용 1개
- 신학 개념 설명 1개

**개수는 3~8개 사이에서 설교의 논리 단위에 맞춰 유연하게** — 개수를 목표로 잡지 않는다:

- 설교의 실제 논리 단위 수를 따른다. 억지로 채우거나 쪼개지 않는다.
- 판별 테스트: "이 조각이 정말 별도 메모로 가치가 있는가?" 두 조각이 50% 이상 겹치면 합친다.
- **한 논지를 설명하기 위한 짧은 비유·사례는 별도 조각으로 만들지 말고 그 논지 조각의 글머리로 흡수**한다. 독립적으로 재사용할 가치가 있는 예화만 별도 조각으로 분리한다.

## 제목 기준

| 항목 | 본 메시지 (argument·exposition·application·doctrine) | 예화 (illustration) |
|---|---|---|
| 길이 | 한국어 **10~20자** | 한국어 **15~25자** |
| 형식 | **명제형** — `X는 Y다` / `X 없이는 Y하지 못한다` / `X가 아니라 Y다` | `💡 {비유명} - {핵심 메시지}` |
| 금지 | 한 단어(`은혜`), 라벨형(`계시의 필요성`, `~에 대하여`, `~의 차이`, `~한 태도`) | `💡` 누락, ` - ` 구분자 누락 |

파일명이 되므로 `:` `?` `/` `\` `*` `<` `>` `|` `"` `#` `^` `[` `]` 를 쓰지 않는다.

**약한 제목 → 강한 제목**

| 약함 (라벨) | 강함 (명제) |
|---|---|
| 인간의 유한성과 계시의 필요성 | 유한한 인간에게 계시는 필수다 |
| 일반계시와 특별계시의 차이 | 일반계시로는 구원에 이르지 못한다 |
| 계시에 대한 올바른 태도 | 말씀 앞에서는 경청이 먼저다 |
| 은혜 | 은혜는 값을 치른 사람이 따로 있다는 뜻이다 |

판별 테스트: 6개월 뒤 검색 결과에서 **제목만 보고 무슨 주장인지 안다면** 좋은 제목이다.

## 글머리(bullets) 기준

- **한 글머리 = 한 아이디어** — 여러 논지를 한 줄에 압축하지 말고 글머리를 나눈다
- 조각당 4~7개 (짧은 조각은 3개 허용), 한국어 10~50자
- 본문 맥락만 사용 — 임의 추론·일반론 금지
- 본문 표현·인용·성경구절 표기를 그대로 살린다 — 설교 속 직접화법은 따옴표로 보존
- **조각당 1~3곳 핵심 주장에 `**볼드**`** — 볼드만 이어 읽어도 설교 논리가 재구성되게. 전부 볼드 금지 (변별력 상실)
- 성경 인용은 독립 글머리로: `구절 표기 — "번역 본문 그대로"` (긴 인용은 `…` 압축 허용)
- `→`는 실천 적용·성찰 질문·귀결 표시 전용, `—`는 주장 뒤 부연·정의 전용
- 설교 결론부의 성찰 질문들은 마지막 조각에 `→` 글머리로 나열

### 예화 조각(`kind: illustration`)의 글머리 3단 구성

1. 예시의 출처·내용 (1~2줄)
2. 핵심 메시지·교훈 (1줄)
3. 이 설교에서 어떻게 적용되었는지 (1줄)

## 기존 조각 재활용 (필수 확인)

`scripts/list_fragments.py`가 목사님 볼트에 이미 있는 조각 제목 목록을 준다.
그 목록에 **의미가 같은 제목이 있으면 새로 짓지 말고 기존 제목을 글자 그대로 쓴다.**

가운뎃점(`·`)과 공백, 어순, 단어 하나 차이가 모두 다른 파일을 만든다.
비슷하지만 다른 제목을 새로 지으면 같은 생각이 조각 두 벌로 갈라진다.

## 조각별 분류

- `doctrine`: config의 `classification.doctrine_values` **허용 목록 안에서만**, 그 조각 내용 기준 1~3개. 적절한 값이 없으면 빈 배열. `use_word: false`면 생략.
  - 설교 전체의 분류를 그대로 복사하지 않는다. 그 조각이 실제로 다루는 주제만 고른다.
- `tags`: 한 단어 한국어 3~8개, **띄어쓰기 절대 금지** (`전능하신하나님` ✓ / `전능하신 하나님` ✗). 너무 일반적인 단어(노트, 정리, 설교) 금지.

## 출력 형식 (JSON)

`build_notes.py --fragments`에 그대로 입력할 수 있는 형식으로 저장한다.
`title` / `kind` / `bullets` / `doctrine` / `tags` **외의 필드는 넣지 않는다.**

```json
{
  "{입력 파일명}": [
    {
      "title": "유한한 인간에게 계시는 필수다",
      "kind": "argument",
      "bullets": [
        "인간은 하나님을 찾을 능력이 아니라 찾을 수 없는 한계를 먼저 안다",
        "[[욥11_7]] — \"네가 하나님의 오묘함을 어찌 능히 측량하며\"",
        "**하나님을 아는 지식은 발견이 아니라 계시로 온다** — 방향이 위에서 아래다",
        "물속의 물고기가 물 전체를 볼 수 없는 것과 같다 — 안에 있는 자는 밖을 보지 못한다",
        "그러므로 신학의 출발점은 인간의 탐구가 아니라 하나님의 말 걸어오심이다"
      ],
      "doctrine": ["🔖계시"],
      "tags": ["계시", "유한성", "하나님지식"]
    },
    {
      "title": "일반계시로는 구원에 이르지 못한다",
      "kind": "exposition",
      "bullets": [
        "[[롬1_20]] — \"그의 보이지 아니하는 것들이… 만물에 분명히 보여 알려졌나니\"",
        "자연과 양심은 하나님이 계시다는 사실까지 알려 준다",
        "**그러나 그분이 누구신지, 어떻게 그분께 나아가는지는 알려 주지 않는다**",
        "같은 본문이 20절에서 알림을, 21절에서 그 알림을 거절한 인간을 말한다",
        "일반계시는 사람을 변명할 수 없게 만들지만 구원하지는 못한다"
      ],
      "doctrine": ["🔖계시", "🔖구원"],
      "tags": ["일반계시", "로마서1장", "변명"]
    },
    {
      "title": "💡 지도 없는 등산객 - 방향 감각만으로는 정상에 못 간다",
      "kind": "illustration",
      "bullets": [
        "산에 오르는 사람이 나침반만 들고 있으면 북쪽은 알지만 등산로는 모른다",

        "→ 그 대목에서 나는 말씀을 조정했는가, 나를 조정했는가"
      ],
      "doctrine": ["🔖순종", "🔖묵상"],
      "tags": ["경청", "말씀묵상", "적용"]

  ]

```

위 예시에서 확인할 것:

- 다섯 조각 모두 제목만 읽어도 설교 논리가 순서대로 재구성된다
- 짧은 비유(물속의 물고기)는 **글머리로 흡수**되고, 재사용 가치가 있는 등산객 비유만 `💡` 조각이 됐다
- 성경 인용은 독립 글머리이고 `[[책장_절]]` 형태다 (링크는 스크립트가 검증한다)
- 마지막 조각에 `→` 성찰 질문이 모였다
- 조각별 `doctrine`이 다르다 — 설교 전체 분류의 복사가 아니다

`kind`는 `argument`(논지) / `exposition`(해석) / `illustration`(예화) / `application`(적용) / `doctrine`(교리 설명) 중 하나.

## 금지

- 본문에 없는 내용을 새로 추가하지 않는다.
- 설교자의 문체를 임의로 고치지 않는다.
- 조각 개수를 억지로 늘리지 않는다.
- 허용 목록에 없는 doctrine 값을 만들지 않는다.
- JSON 스키마 밖의 필드·섹션·설명문을 추가하지 않는다.
- `## 관련 노트`, `See also`, `References` 같은 링크 모음을 만들지 않는다. 노트 본문 구조는 스크립트가 전부 결정한다.
