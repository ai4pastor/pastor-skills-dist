# WORD Classify Prompt

설교 전체를 목사님 개인 분류 체계(WORD: World·Outcome·Route·Doctrine)에 따라 분류를 **제안**한다.
확정은 dry-run 미리보기에서 목사님 승인으로 이루어진다.

## 절대 원칙

- 모든 값은 config `classification`의 허용 목록(`world_values`/`outcome_values`/`route_values`/`doctrine_values`) **안에서만** 고른다.
- 목록에 없는 값은 비슷해 보여도 **절대 새로 만들거나 변형하지 않는다.** 적절한 값이 없으면 그 항목을 비워 두고 보고에 남긴다.
- 허용 목록 자체를 수정하지 않는다. 목록에 추가가 필요하면 목사님이 config를 직접 갱신하도록 안내한다.

## 분류 지침

- **world**: 설교의 영역·사역 맥락. 1~2개.
- **outcome**: 산출물 종류. 보통 1개 (이미 설교한 원고라면 설교에 해당하는 값).
- **route**: 처리 상태. 보통 1개 (이미 설교한 원고라면 완료에 해당하는 값).
- **doctrine**: 설교의 신학 주제. 3~6개.
  - 광범위한 값보다 구체적인 값을 우선한다.
  - 본문 전체 흐름 기준으로 고른다 (조각별 분류는 split_fragments에서 따로 한다).

## tags 지침

- 한 단어 한국어 3~8개.
- **띄어쓰기 절대 금지** — 공백이 생기면 반드시 붙여서 한 단어로 만든다 (`역사적증거` ✓ / `역사적 증거` ✗).
- doctrine과 의도적으로 겹치지 않게 한다 (doctrine에 이미 있는 주제는 tags에서 다른 각도로).
- 너무 일반적인 단어(노트, 정리, 설교, 말씀) 금지.

## 입력

- 설교 본문 텍스트 (4,000자 초과 시 앞부분 중심으로 판단하되 결론부도 확인)
- config의 허용 목록 4종

## 출력 형식 (JSON)

`build_notes.py --word`에 그대로 입력할 수 있는 형식으로 저장한다:

```json
{
  "{입력 파일명}": {
    "world": ["허용 목록 값"],
    "outcome": ["허용 목록 값"],
    "route": ["허용 목록 값"],
    "doctrine": ["허용 목록 값 3~6개"],
    "tags": ["한단어태그 3~8개"]
  }
}
```
