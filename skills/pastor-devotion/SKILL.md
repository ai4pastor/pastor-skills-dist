# pastor-devotion — 설교 한 편이 닷새의 묵상이 됩니다

주일에 선포하신 설교가 주일 하루로 끝나지 않도록, 성도들이 월요일부터 금요일까지
하루 5분씩 붙들 수 있는 **5일 묵상 자료**를 만들어 드립니다.

- 산출물은 **HTML 파일 딱 하나**입니다 (디자인·동작 전부 내장).
  카카오톡 대화방에 파일로 올리기만 하면 성도들이 폰·PC 어디서든 바로 봅니다.
- 하루치 구성: 오늘의 성경 구절 → 짧은 묵상 → 적용 질문 두 개 → 기도문.
- 원본 설교 파일은 **읽기만 하고 절대 수정하지 않습니다.**

## Step 0. 설교 파일 받기 + 본문 추출

먼저 나만의 규칙 파일이 있는지 확인한다:

```bash
python3 scripts/devotion_paths.py
```

`devotion_rules_exists: true`면 그 파일(**나만의 규칙**)을 읽고 이후 모든 단계에
덧입힌다 — 기본 대상·기본 시안이 적혀 있으면 Step 1에서 묻는 대신 "지난번처럼
{대상}·{시안}으로 할까요?"라고 확인만 한다. (아래 "개인화" 절 참고)

목사님이 파일 경로를 주시면 (또는 대화에 끌어다 놓으시면) 확인 후 추출한다:

```bash
python3 scripts/extract_text.py "{설교 파일 경로}"
```

- JSON의 `text`가 설교 본문이다. 캐시되므로 다시 실행해도 재변환하지 않는다.
- `.hwp`·`.pdf` 등에서 변환 도구가 없다는 안내가 나오면 `ensure_tools.py --check`로
  상태를 보여 드리고, **설치 여부를 여쭤본 뒤에만** `ensure_tools.py --install …`을
  실행한다 (시스템을 건드리지 않는 격리 설치).
- `warnings`는 그대로 전한다 — `scanned_pdf`(글자 없는 스캔 이미지)면 다른 형식의
  원고를 부탁드리고, `short_text`(200자 미만)면 파일이 맞는지 여쭤본다.
- 파일이 아니라 설교 본문을 채팅에 붙여 넣으셨다면 그 텍스트를 그대로 쓴다
  (이 경우 저장 위치만 여쭤본다 — 기본 제안: 다운로드 폴더).

## Step 1. 두 가지만 여쭤보기

질문은 이 둘뿐이다. 저장 위치는 묻지 않는다 (설교 파일 옆에 저장).

**① 묵상 대상** — 누구에게 나눠 주실 자료인가요?

| 대상 | 문체·내용 |
|---|---|
| 어린이부 | "~해요" 체, 한 문장 15자 안팎, 쉬운 낱말만, 학교·놀이·가족 비유, 기도문 3줄 |
| 청소년부 | 친근한 존댓말, 한 문장 25자 안팎, 학교·친구·일상 비유 |
| 장년 | 정중한 존댓말, 삶의 자리(가정·일터·관계) 적용, 설교의 신학 용어를 존중하되 한 번씩 풀어쓰기 |
| 전교인 | 온 세대가 함께 읽는 쉬운 존댓말, 가정예배에서 함께 읽도록 안내 한 줄 포함 |

**② 디자인** — 일곱 가지 시안 중 하나 (색상 체계가 저마다 다르다):

| 시안 | 분량 | 느낌 | 어울리는 자리 |
|---|---|---|---|
| `poster` | 8장 | 미니멀 포스터 — 하루 한 장, 큰 숫자, cream+coral | 처음 써 보실 때, 폰 중심 |
| `classic` | 16장 | 정갈한 정형 — 모든 날이 같은 박자, cream+coral | 차분한 본문 중심 |
| `narrative` | 19장 | 이야기 흐름 — 어두운 전환점 강조, cream+coral | 스토리가 강한 설교 |
| `dawn` | 12장 | 심야에서 새벽으로 밝아지는 진행, 네이비→앰버 | 새벽기도회 |
| `journal` | 10장 | 묵상 일기장 — 줄노트·체크박스·손글씨, 페이퍼+세이지 | 개인 묵상, 청년 |
| `liturgy` | 9장 | 기도서 정서 — 부름·봉독·응답·축도 리듬, 네이비+골드 | 장년, 전통 예배 |
| `card` | 10장 | SNS 카드뉴스 — 하루 한 장 비비드 컬러 블록 | 청소년, 단체방 공유 |

처음이시면 `poster`를 권해 드린다 (분량이 가볍고 폰 화면에 가장 잘 맞는다).
대상을 먼저 여쭤봤으므로, 대상과 어울리는 시안 1~2개를 함께 추천해 드린다.

## Step 2. 5일 구조화 + 미리보기 승인

설교 본문을 읽고 다음을 뽑는다: **핵심 명제 1문장 · 중심 성경 본문 · 핵심 대지 3개
· 적용 포인트 · 날마다 하나씩, 그날 주제를 가장 잘 담은 원문 문장(발췌 후보)**.
그리고 닷새에 배분한다:

| Day | 내용 |
|---|---|
| 1 (월) | 도입 — 설교의 핵심 명제를 가장 친근한 비유와 함께 |
| 2 (화) | 핵심 1 — 첫 번째 대지 + 뒷받침 구절 + 원문 발췌 |
| 3 (수) | 핵심 2 — 두 번째 대지 + 뒷받침 구절 + 원문 발췌 |
| 4 (목) | 핵심 3 — 세 번째 대지 + 뒷받침 구절 + 원문 발췌 |
| 5 (금) | 마무리 — 종합 + 한 주 적용 + 다짐 |

**묵상의 뼈대는 목사님의 육성이다.** 매일 "주일 말씀 중에서" 발췌가 들어가고,
핵심 한 줄·묵상 단락·적용 질문은 그 발췌를 풀어쓰는 방식으로 만든다 —
설교와 무관한 새 비유·새 주장을 지어내지 않는다.

대지가 3개가 안 나오는 설교(단일 주제 강해 등)는 억지로 쪼개지 말고 흐름
(문제 제기 → 본문의 답 → 삶의 반응)으로 Day 2~4를 구성한다.

날마다 이 필드를 만든다 (분량 규율 — 넘치면 슬라이드가 깨진다):

```json
{
  "label": "하루 이름",            // 8자 이내
  "title_line1": "제목 윗줄",       // 8자 이내
  "title_line2": "제목 아랫줄.",    // 10자 이내, 마침표 포함
  "subhead": "부제 한 문장",        // 30자 이내
  "scripture": "성경 구절 본문",     // 50자 이내, 설교가 인용한 번역 그대로
  "scripture_cite": "요한복음 16:24",
  "sermon_quote": "설교 원문 발췌",   // 원문 문장 1~2개를 글자 그대로 — 목사님 육성

  "key1": "핵심 인용 윗줄,",        // 12자 이내
  "key2": "핵심 인용 아랫줄.",
  "med_p1": "묵상 1단락",           // 80~120자
  "med_p2": "묵상 2단락",           // 80~120자
  "app_headline": "한 가지만 골라, 오늘 마음에 두기.",
  "q1": "적용 질문 1",              // 50자 이내, "오늘"/"이번 주"로 한정
  "q2": "적용 질문 2",
  "prayer": "기도문"                // 3~4행, \n 구분
}
```

**콘텐츠 규율 (어길 수 없음):**

- `sermon_quote`(주일 말씀 발췌)는 **설교 원문 문장을 글자 그대로** 쓴다.
  생략은 문장 경계에서 `…`로만, 조사·어미 하나도 바꾸지 않는다.
- 성경 구절은 **설교 본문에 인용된 구절에서만** 가져온다. 설교에 없는 구절을
  지어내거나 기억으로 채우지 않는다 — 필요하면 장절 표기만 하고 본문 인용은 비운다.
- 묵상·적용은 그날의 발췌를 풀어쓰는 것이지 새 설교를 쓰는 것이 아니다.
  핵심 한 줄(key1/key2)도 원문의 어휘를 살려 압축하고, 설교에 없는 신학적
  주장·비유를 보태지 않는다.
- 적용 질문은 "오늘/이번 주 + 한 가지 행동"으로 좁힌다.

**발췌·인용 기계 검증 (필수)** — 5일치 `sermon_quote`와 `scripture`를 JSON 배열로
모아 원문과 대조한다. 실패한 발췌는 원문에서 다시 뽑는다:

```bash
python3 scripts/verify_quotes.py --source "{추출 JSON}" --quotes "{발췌 JSON}"
```

구조화가 끝나면 **5일 매핑을 표로 먼저 보여 드리고** (Day별 제목·구절·발췌·핵심
한 줄) 승인을 받은 뒤에 HTML을 만든다. 고치고 싶은 날만 말씀하시면 그 날만 다시 짠다.

## Step 3. HTML 한 장 빌드

선택된 시안의 본보기 `templates/template_{시안}_example.html` 을 **반드시 Read 하고**
같은 디자인 어휘로 새 콘텐츠를 채운다. 본보기의 슬라이드 구조·장수·CSS를 그대로
따르고 텍스트(와 일러스트)만 새 설교로 바꾼다.

**공통 불변 규칙 (모든 시안, 변경 금지):**

- 폰트: 나눔명조 ExtraBold (제목, Google Fonts) + SUIT (본문, jsdelivr CDN)
  — 유일한 외부 의존. 인터넷이 없으면 기본 명조/고딕으로 표시된다.
  (journal 만 손글씨용 Nanum Pen Script 를 추가로 쓴다)
- 데스크톱(≥834px) 16:9 슬라이드 / 모바일(<833px) `100dvh` 풀스크린 자동 분기
- 모든 한국어 텍스트에 `word-break: keep-all; overflow-wrap: break-word;`
- 키보드 ←→/Space + 터치 스와이프 + 좌우 클릭 내비게이션

**팔레트는 시안별이다 — 각 본보기의 `:root` 토큰이 정본.** 임의로 색을 바꾸거나
시안끼리 섞지 않는다 (poster·classic·narrative = cream/coral, dawn = 네이비→앰버,
journal = 페이퍼/세이지, liturgy = 네이비/골드, card = stripe 비비드).
- 표지에 설교 제목·성경 본문·날짜(파일명이나 본문에서 추론)를 넣는다.
  교회 이름은 설교 원고에 적혀 있을 때만 넣는다.
  **파일명과 본문 내용이 서로 다르면 본문을 믿고**, 다르다는 사실을 목사님께
  알린다 (실제로 파일명은 지난주 제목인 경우가 있다).

**SVG 일러스트** — 본보기가 일러스트를 쓰는 시안(classic·narrative)에서만.
`<symbol>`로 인라인, 슬라이드에서 `<use>` 참조. coral 단색 stroke, 1024×1024
viewBox, 손그림 느낌 미니멀 라인. 본보기의 SVG를 그대로 쓰지 말고 **이 설교의
다섯 주제**에 맞는 상징으로 새로 그린다. poster 는 타이포그래피만 쓴다.

**HTML에 넣으면 안 되는 것:** 파일 경로, 목사님 컴퓨터의 폴더 이름 등 개인
식별정보. 푸터는 시리즈 제목과 Day 표시만.

## Step 4. 저장 + 확인 안내

- 저장: 설교 파일과 같은 폴더에 `{설교 파일명}_5일묵상.html`
  (예: `260719_주일설교_기도.docx` → `260719_주일설교_기도_5일묵상.html`)
- **같은 이름이 이미 있으면 덮어쓰지 않고** `_5일묵상_2.html`처럼 번호를 붙인다.
- 저장 후 스스로 점검한다: Day 1~5 슬라이드가 모두 있는가, "주일 말씀 중에서"
  발췌가 날마다 있는가, `verify_quotes.py`가 발췌·성경 구절 전부 통과했는가,
  분량 규율을 넘긴 필드가 없는가.
- 목사님께 안내한다:
  1. 파일을 더블클릭해 브라우저에서 한번 훑어보시라고 (수정하고 싶은 문구는
     말씀만 하시면 바로 고친다)
  2. 공유 방법: **카카오톡 대화방에 이 HTML 파일을 그대로 첨부**하면 성도들이
     열어 볼 수 있다. 교회 홈페이지나 밴드에 올려도 된다.

## 개인화 — 두 가지 길

**① 나만의 규칙 (권장 — 업데이트에 안전).** 목사님이 "묵상 문체를 바꾸고 싶다",
"우리 교회는 항상 장년·poster로", "기도문을 더 길게" 같은 취향을 말씀하시면
**스킬 파일을 고치지 말고** `devotion_paths.py`가 알려 준 `devotion_rules.md`
파일을 만들어 드린다. 담을 수 있는 것: 기본 대상·기본 시안·문체 취향·기도문
길이·교회 이름 표기·표지 문구 취향. 이 파일은 스킬 폴더 밖에 있어 플러그인을
업데이트해도 유지되고, 실행 때마다 문체 규칙보다 우선 적용된다.
단, **안전 원칙은 규칙 파일로도 바꿀 수 없다**: 원본 비수정 · 덮어쓰기 금지 ·
성경 구절과 발췌를 지어내지 않기(`verify_quotes.py` 검증) · 미리보기 승인.

**② 내 이름의 스킬로 복제 (구조까지 바꾸고 싶을 때).** "이 스킬을 내 것으로
복사해서 ○○를 바꿔줘"라고 하시면 이 스킬 폴더 전체를
`~/.claude/skills/{원하시는 이름}/` (예: `kim-devotion`)으로 복사하고, SKILL.md
frontmatter의 `name:`을 폴더명과 같게 바꿔 드린다. 이후 `/{그 이름}`으로
호출되는 완전한 개인 스킬이 된다. 복사 전에 꼭 알려 드릴 것: **복제본은
업데이트를 받지 못한다** — 원본 스킬의 버그 수정·새 시안이 반영되지 않으므로,
취향 조정이 목적이면 ①을 먼저 권해 드린다.

## 절대 규칙

1. **설교 원본은 절대 수정하지 않는다** — 읽기 전용.
2. **기존 파일을 덮어쓰지 않는다** — 이름이 겹치면 번호를 붙인다.
3. **성경 구절과 "주일 말씀" 발췌를 지어내지 않는다** — 설교가 인용한 본문과
   원문 문장 그대로만 쓰고, `verify_quotes.py`로 기계 검증한다.
4. **HTML 생성 전에 5일 매핑 미리보기 승인을 받는다.**
5. 변환 도구 설치는 **여쭤본 뒤에만**, 격리 폴더에만 한다.
